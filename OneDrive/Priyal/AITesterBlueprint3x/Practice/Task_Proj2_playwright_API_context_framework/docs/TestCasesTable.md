# Playwright API Testing Framework - Test Case Matrix

This document provides a detailed list of all API test cases implemented in the framework. These test cases validate critical user journeys, edge cases, negative flows, rate limiting, and security vulnerabilities (such as injection attempts) against simulated Amazon Login endpoints.

| TC ID | Category | Endpoint | Test Objective | Input / Payload Highlights | Expected Status | Expected Validations / Assertions |
|---|---|---|---|---|---|---|
| **TC_01** | Critical Path | `POST /ap/signin`<br>`GET /ap/secure-profile` | Verify login with valid credentials followed by retrieving a protected customer profile using the returned authorization token. | `email`: "valid_user@amazon.in"<br>`password`: "password123" | 200 (Signin)<br>200 (Profile) | 1. Signin returns `status: "success"` and a valid token.<br>2. Secure Profile returns accurate name ("Priyal Desai"), email, and Prime status. |
| **TC_02a** | Negative | `POST /ap/signin` | Verify login fails when a correct email is provided but with an incorrect password. | `email`: "valid_user@amazon.in"<br>`password`: "wrongPassword" | 401 | 1. Response status is 401 (Unauthorized).<br>2. JSON error is "Unauthorized".<br>3. Message equals "Invalid credentials. Password or email is incorrect." |
| **TC_02b** | Negative | `POST /ap/signin` | Verify login fails when using an unregistered or non-existent email address. | `email`: "nonexistent@amazon.in"<br>`password`: "password123" | 401 | 1. Response status is 401 (Unauthorized).<br>2. Error message matches invalid credential warning. |
| **TC_02c** | Negative | `POST /ap/signin` | Verify login fails when both email and password are provided as empty strings. | `email`: ""<br>`password`: "" | 401 | 1. Response status is 401 (Unauthorized).<br>2. Returns appropriate authentication error. |
| **TC_03a** | Edge Case (Tampering) | `POST /ap/signin` | Verify bad request status when the `password` field is entirely missing from the JSON payload. | `email`: "valid_user@amazon.in"<br>(password omitted) | 400 | 1. Response status is 400 (Bad Request).<br>2. JSON error is "Bad Request".<br>3. Message equals "Missing email or password parameter." |
| **TC_03b** | Edge Case (Tampering) | `POST /ap/signin` | Verify bad request status when the `email` field is entirely missing from the JSON payload. | `password`: "password123"<br>(email omitted) | 400 | 1. Response status is 400 (Bad Request).<br>2. JSON error is "Bad Request".<br>3. Message equals "Missing email or password parameter." |
| **TC_04a** | Security | `POST /ap/signin` | Verify API blocks authentication attempts containing SQL Injection payloads in the email field. | `email`: "valid_user@amazon.in' OR '1'='1"<br>`password`: "password123" | 403 | 1. Response status is 403 (Forbidden).<br>2. Error is "Forbidden".<br>3. Message highlights SQL Injection security block. |
| **TC_04b** | Security | `POST /ap/signin` | Verify API blocks authentication attempts containing SQL Injection comment-based comments in the password field. | `email`: "valid_user@amazon.in"<br>`password`: "' OR 1=1 --" | 403 | 1. Response status is 403 (Forbidden).<br>2. Error is "Forbidden".<br>3. Injection block warning matches payload filter. |
| **TC_05a** | Security | `GET /ap/secure-profile` | Verify a protected endpoint is inaccessible if the Authorization header is missing. | (No headers sent) | 401 | 1. Response status is 401 (Unauthorized).<br>2. Error is "Unauthorized".<br>3. Message equals "Missing Authorization header." |
| **TC_05b** | Security | `GET /ap/secure-profile` | Verify a protected endpoint denies access if the Authorization header uses an invalid scheme (non-Bearer). | `Authorization`: "Token valid_jwt..." | 400 | 1. Response status is 400 (Bad Request).<br>2. Error is "Bad Request".<br>3. Message contains "Invalid Authorization header format". |
| **TC_05c** | Security | `GET /ap/secure-profile` | Verify a protected endpoint denies access when the token value itself is invalid or tampered with. | `Authorization`: "Bearer invalid_jwt..." | 403 | 1. Response status is 403 (Forbidden).<br>2. Error is "Forbidden".<br>3. Message contains "Invalid authentication token". |
| **TC_06a** | Negative | `GET /ap/secure-profile` | Verify access is denied when utilizing an expired access token. | `Authorization`: "Bearer expired_jwt..." | 401 | 1. Response status is 401 (Unauthorized).<br>2. Error is "Unauthorized".<br>3. Message equals "Authorization token has expired." |
| **TC_06b** | Negative | `POST /ap/token` | Verify token refresh fails when attempting to use an expired refresh token. | `refreshToken`: "expired_refresh_token" | 401 | 1. Response status is 401 (Unauthorized).<br>2. Error is "Unauthorized".<br>3. Message equals "Refresh token has expired." |
| **TC_06c** | Critical Path | `POST /ap/token` | Verify token refresh succeeds and returns a new active authorization token. | `refreshToken`: "refresh_token_999" | 200 | 1. Response status is 200.<br>2. Response contains `status: "success"` and a refreshed token. |
| **TC_07a** | Edge Case (Rate Limit) | `POST /ap/signin` | Verify explicitly rate-limited test accounts are blocked instantly by the application. | `email`: "ratelimit@amazon.in"<br>`password`: "password123" | 429 | 1. Response status is 429 (Too Many Requests).<br>2. JSON error is "Too Many Requests".<br>3. Message contains "Account locked". |
| **TC_07b** | Edge Case (Rate Limit) | `POST /ap/signin` | Verify client IP rate-limiting blocks rapid multiple API hits (brute-force prevention) after 5 requests. | Multi-hit loop: 5 failed requests sequentially, followed by a 6th request. | 429 | 1. First 5 requests return 401 (or other non-429 codes).<br>2. 6th request returns 429 (Too Many Requests).<br>3. Response contains a header `Retry-After: 60`. |
